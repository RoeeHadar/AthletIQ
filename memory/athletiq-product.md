# AthletIQ product

## Must never miss

- Working name is **AthletIQ** — use it in Charter, PRD, and all project artifacts.
- **Product vs project purpose:** PRD = sports analytics + NBA ingestion/analysis + pre-game win/lose predictions via API; Charter = portfolio/engineering-demonstration objectives and deliberate **technical constraints** (Docker, FastAPI, GHA, API-Sports, LR/XGBoost families). Solo **personal/portfolio** GitHub build — not an organizational product (yet).
- Core product: sports API → Python ETL → PostgreSQL → SQL analytics → feature engineering → ML (game-outcome prediction) → FastAPI → Docker → GitHub Actions CI/CD.
- **Personas:** primary product user = sports/data **analyst or developer** (local/API); project **stakeholder** = project owner; **artifact audience** = technical reviewers (not product users).
- **MVP prediction / ML temporal invariant:** pre-game home win/lose — binary outcome + `P(home team wins)` (designated team = **home team**, SRS ML-002). No information generated **after** a game's prediction timestamp may influence its **features, training, model selection, or evaluation** (no leakage).
- **MVP models:** **two baselines** (naive: always home; domain-informed: better pre-game season win rate, tie → home) + **logistic regression + XGBoost** on a **temporal train / validation / test** split (ML-003): **~70% / ~15% / ~15%** oldest→newest by `game_start_time` (no random shuffle). **Selection** on **validation** log loss only (ML-007, ADR-003; tie → LR); **test once** for final ML-005 report. At least one ML model must beat the **domain-informed** baseline on **test log loss** (primary); accuracy secondary. **Historical depth / active window:** **2 Must / ≤3 Should** most recent **completed** NBA seasons (DR-001); seasons **outside** that window = **too old** — do not ingest; prune from raw + curated (roster/coach drift).
- **MVP features (Gate 4 design):** **team-level only** — win rate, point differential, points scored/allowed (means over **last 5 & last 10** games before tip) + season win rate to date; **cold start (decided):** if fewer than **`min_prior_games = 5`** completed games before tip → season-to-date aggregates (fixed for MVP, not an open parameter). **No player-level features in MVP.**
- **Data quality / prune (Gate 4 design):** skip invalid/noisy rows + count in validation report; dedupe by provider natural key; fail pipeline if zero teams or zero games for a required season after load. Provider HTTP: exponential backoff + jitter, max **5** retries, honor `Retry-After`; then fail stage.
- **Model artifacts (Gate 4 design):** **joblib** binary + **JSON** metadata (`model_version`, `feature_version`, `dataset_version`, `code_commit`, `training_config`, metrics, selection pin) per ML-009 / ADR-004.
- **Training–serving consistency (ML-008):** same documented feature definitions + preprocessing (`feature_version`) for train and inference.
- **Data source:** **API-Sports NBA** (free tier) locked for MVP via ADR-002; all provider I/O through adapter boundary. PRD kept provider abstract; Charter named API-Sports as discovery selection.
- **Architecture locks (Gate 3 Approved):** PostgreSQL; immutable raw JSON FS (ADR-006); idempotent loads; Python-orchestrated batch; local artifacts + selection pin; API **`game_id` BIGINT** (decimal string) + precomputed `(game_id, feature_version)` (ADR-008, **ADR-010**); sync predict; lineage (FR-014/ML-009); **no application auth** on MVP demo API (ADR-009 — localhost/Compose only); GHA lint/unit/integration/image only (NFR-003); **NFR-004** no hard latency/availability SLOs; **NFR-005** DB indexes for local analytics/feature paths; GCP future only (ADR-007 non-binding). Binding ADRs: **001–006, 008, 009, 010**.
- **API error behavior (Gate 4 design):** distinct codes — `game_not_found` vs `features_not_found`; **`db_unavailable` → 503** (not generic 500); **`model_unavailable` → 503** on `/v1/health`, `/v1/predict`, `/v1/model`; **no silent baseline fallback** on missing model.
- **ML ops (Gate 4 design, MVP):** monitoring = validation/eval reports + `/v1/health` + structured logs; retraining = **manual/operator-invoked** pipeline only — no drift dashboards or automated retrain (PRD non-goal).
- Document **both** MVP scope **and** post-MVP/full roadmap everywhere relevant. Post-MVP: richer predictions (score/spread), NumPy NN from scratch after working LR/XGBoost (no PyTorch), optional second league adapter, minimal prediction UI — still no betting product.
- **Goals (success):** (1) reproducibility — clone + documented env reproduces pipeline/evaluation without manual source edits, (2) data quality — ETL validates fields, handles invalid/duplicates per rules, reproducible validation report, (3) baseline + LR + XGBoost vs baseline on same holdout, (4) FastAPI serves binary + probability predictions, (5) GHA lint → unit → integration → image build, (6) documented evaluation methodology + known limitations (honest ML, not "accurately predicts games").
- **Non-goals:** no betting/odds product, no mobile app, no multi-tenant SaaS, no live in-game prediction, no paid user accounts, **no production-grade ML ops** (feature store, automated retraining, A/B testing, drift monitoring as required MVP capabilities) — demo API + docs only.
